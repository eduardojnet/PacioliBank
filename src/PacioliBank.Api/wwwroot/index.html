PacioliBank Ledger

Painel de evidência: quatro demonstrações, cada uma provando uma decisão de arquitetura contra a API real. Não há cadastro aqui, nem endpoint próprio: o painel usa a mesma API pública de qualquer integrador.

Material de demonstração, sem teste automatizado próprio (ADR-0011). A prova que importa está na suíte de testes; aqui ela fica visível.

1. Disparo concorrente

ADR-0005

A conta recebe saldo para exatamente 10 débitos de 10,00. Em seguida, 50 débitos são disparados de uma vez. O bloqueio por conta serializa as escritas: exatamente 10 passam, 40 são recusados por saldo, e a posição nunca fica negativa.

2. Linha do tempo

ADR-0003

O ledger é a única fonte da verdade, e a posição é derivada dele. Por isso a posição de qualquer instante passado sai do mesmo dado, sem estrutura extra. Os lançamentos têm data do fato retroativa, embora todos tenham sido registrados agora (RN-009, RN-012).

    3. Reenvio idempotente

    ADR-0006

    O mesmo crédito é enviado duas vezes com a mesma Idempotency-Key, como faria um cliente após um timeout. A segunda resposta é a original, byte a byte, lida do registro: nenhum lançamento novo, posição inalterada. Mesma chave com outro valor é conflito.

    4. Origem do cálculo

    ADR-0007

    Um snapshot é gravado a cada 100 lançamentos, na própria transação. A posição corrente é o snapshot mais os lançamentos posteriores. computedFrom diz de onde veio o cálculo, e entriesReplayed quantos lançamentos foram somados além do snapshot.
